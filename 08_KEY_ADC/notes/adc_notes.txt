----------------------------------------------------------------
 [1] 电压换算为什么强转 uint32_t 又转回 uint16_t?
----------------------------------------------------------------
 £★ 说明:
   uint16_t usMv = (uint16_t)((uint32_t)ulResult * 2500UL / 4095UL);
   小类型存结果, 大类型算过程.
   中间值 ulResult * 2500 最大 10237500, uint16 上限 65535,
   不抬 32 位乘法直接溢出; 2500UL 的 UL 后缀同理.
   除完 4095 结果最大 2500, uint16 装得下, 存 16 位省内存.


----------------------------------------------------------------
 [2] 电压显示算法套路 (阈值触发 + 统一刷新出口)
----------------------------------------------------------------
 £★ 说明:
   1) 换算: usMv = result * 2500UL / 4095UL, 单位 mV (见 [1]).
   2) 阈值触发: lDiff = (int32_t)usMv - (int32_t)usLastMv,
      |lDiff| > 300 (0.3V) 才更新显示;
      必须用 int32_t 做差, uint16 直接减会下溢出鬼值.
   3) 首刷: usLastMv 初值 0xFFFF (不可能的电压值),
      首帧 lDiff 必然超阈值, 强制刷一次.
   4) 拆位显示: "ADC: %d.%dV",
      整数位 usMv / 1000, 小数位 (usMv % 1000) / 100.
   5) 刷新出口: 多行内容各判各的 (status / 电压),
      谁变了都置 bNeedRefresh = 1, 循环末尾统一:
      if (bNeedRefresh) { bNeedRefresh = 0; OLED_Refresh(); }
      ShowString 只写显存随便调, Refresh 250ms 必须守出口.
