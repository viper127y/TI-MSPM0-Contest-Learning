----------------------------------------------------------------
 [1] OLED 显存数据映射 (屏幕简介)
----------------------------------------------------------------
 £★ 说明:
   SSD1306 显存分 8 个页 (Page0~Page7), 每页 128 个段
   (Segment0~Segment127), 每段 8 个位 (D0~D7);
   每个位对应 1 个像素点, 段内从上往下对应 D0~D7.
   例: 向 Page0 Segment0 写入 0xFF, 该段 8 个像素全亮.

----------------------------------------------------------------
 [1] DL 库读引脚和 HAL 有什么区别?
----------------------------------------------------------------
 £★ 说明:
   HAL_GPIO_ReadPin 返回 0/1; DL_GPIO_readPins 返回位掩码
   (非 0 即高). 所以要转:
   uchPinLevel = (DL_GPIO_readPins(port, pin) != 0) ? 1u : 0u;
   函数原型在 C:\ti\mspm0_sdk_2_11_00_07\source\ti\driverlib\dl_gpio.h.
   IDE 跳不过去是因为 key.h 用宏 include (#include TI_IC_DL),
   索引器跟不了, 编译能过就不用管.


----------------------------------------------------------------
 [2] 按键驱动使用套路是什么?
----------------------------------------------------------------
 £★ 说明:
   填结构体 (6个字段) -> emBtnDeviceInit -> 每 10ms 调 vBtnExecute
   -> emBtnGetEvent / vBtnClearEvent.
   阈值单位是"调用次数"不是毫秒: 消抖 3 (30ms), 长按 100 (1s),
   双击窗口 20 (200ms).
   事件处理后必须 vBtnClearEvent, 否则重复触发.


----------------------------------------------------------------
 [3] 为什么结构体没填完会"按了没反应"?
----------------------------------------------------------------
 £★ 说明:
   局部变量没赋值的字段是栈上垃圾值. ulDebounceCountThreshold
   是随机数时, 消抖计数永远够不到阈值 -> 状态永远是"释放"
   -> 永远没有事件.
   结论: 6 个字段一个不落全填上.


----------------------------------------------------------------
 [4] emActiveLevel 怎么填? 配置和实测不一致信谁?
----------------------------------------------------------------
 £★ 说明:
   信实测. 本板实测: 松手 raw=1, 按下 raw=0
   -> 填 emBtnActiveLevel_Low.
   填反的症状: 驱动世界是镜像的, 单击永远不触发, 只报 LongPress.


----------------------------------------------------------------
 [5] 为什么 OLED 每圈都刷会让按键"很久才响应"?
----------------------------------------------------------------
 £★ 说明:
   OLED_Refresh 约 250ms (I2C 100kHz x 1000+ 字节),
   每圈都刷把循环拖成 500ms.
   按键阈值单位是调用次数, 被放大 50 倍: 消抖 3 次 = 1.5s,
   单击确认 20 次 = 10s.
   解法: 显示内容变化才刷屏 (记 iLastFlag, 变了才 OLED_Refresh).


----------------------------------------------------------------
 [6] SysTick 滴答定时器怎么写?
----------------------------------------------------------------
 £★ 说明:
   static volatile uint32_t s_ulSysTick = 0;
   SysTick_Config(CPUCLK_FREQ / 1000);        // 80MHz -> 1ms 心跳
   void SysTick_Handler(void) { s_ulSysTick++; }
   // 中断只数数, 不干活

   主循环调度用无符号减法 (天然免疫溢出):
   if ((uint32_t)(s_ulSysTick - ulLastScan) >= 10) {
       ulLastScan = s_ulSysTick;
       vBtnExecute(...);
   }
   volatile 不能删 (中断与主循环共享);
   不要写成 s_ulSysTick >= ulLastScan + 10 (溢出会死).


----------------------------------------------------------------
 [7] SysTick 框架加上后按键还是慢, 为什么?
----------------------------------------------------------------
 £★ 说明:
   扫描不在中断里, 是主循环的 if 在看 tick.
   主循环卡在 250ms 刷屏上, if 就 250ms 才被检查一次.
   两条规则缺一不可:
   1) 时间戳调度
   2) 显示变了才刷.
